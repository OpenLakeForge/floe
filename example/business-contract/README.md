# Business contract template

`domain-template.xlsx` is the workbook a business analyst fills in **once per domain**.
It describes tables and columns in business terms. It holds no paths, credentials,
catalogs or partitioning.

> **Status:** this is the template and its specification only. `floe contract import`
> does not exist yet (tracked in #1449). The mapping below is the contract the importer
> will implement.

## Workflow

```
Excel  →  floe contract import  →  business-only entity YAML + one _domain.yml  →  floe validate
                                    (engineer completes _domain.yml once)
```

1. The business fills the workbook.
2. The importer writes one `domains/<domain>/<target_table>.yml` per table, plus a
   `_domain.yml` scaffold.
3. The data engineer completes `_domain.yml` once (source and sink), then runs `floe validate`.

## Tabs

| Tab | Purpose |
|---|---|
| `Guide` | Instructions and three input cells: `domain`, `template_version`, `default_severity`. |
| `Tables` | One row per target table. |
| `Columns` | One row per target column, grouped as 01 Names & types, 02 Keys & relationships, 03 Quality checks. |

Conventions: `X` (any case) switches a checkbox on, blank is off. `allowed_values` are
separated by `|`. `pattern` uses the Rust/Polars regex dialect (no lookaround, no
backreferences). Blank severity inherits.

## Field → YAML mapping

### Guide and Tables

| Workbook | Floe entity YAML |
|---|---|
| `Guide.domain` | `domain` |
| `Guide.default_severity` | `policy.severity` (default for every check) |
| `Tables.target_table` | `name`, the file name, and the default Iceberg table name and sink path (`{{entity.name}}`) |
| `Tables.source_dataset` | `source.resource`, consumed as `{{resource}}` by the engineer's domain source path. A logical export name, not a path |
| `Tables.owner` | `metadata.owner` |
| `Tables.description` | `metadata.description` |
| `Tables.default_severity` | `policy.severity` for this table (overrides the Guide) |
| `Tables.unique_severity` | `policy.rule_severity.unique` (one per table; Floe has no per-key severity) |
| `Tables.not_null_severity` | `policy.rule_severity.not_null` |
| `Tables.cast_severity` | `policy.rule_severity.cast_error`: values that cannot be converted to `target_type` (bad dates, numbers) |
| `Tables.business_name`, `Tables.grain` | Business metadata only (comments) |

### Columns

| Workbook | Floe entity YAML |
|---|---|
| `source_column` | `schema.columns[].source` (blank = same as `target_column`) |
| `target_column` | `schema.columns[].name` |
| `target_type` | `schema.columns[].type` (`string`, `int64`, `float64`, `decimal(p,s)`, `boolean`, `date`, `datetime`, ...) |
| `primary_key` = X | `schema.primary_key`. Several rows of one table form one composite key, in row order. Implies not-null |
| `unique` = X | `schema.unique_keys`: a single-column key |
| `unique_group` (`U1`, `U2`) | `schema.unique_keys`: rows sharing a label form one composite key. One group per row |
| `not_null` = X | `nullable: false` |
| `not_null_severity` | the column's `not_null` rule severity |
| `min`, `max` | `min`, `max` column checks (rule `out_of_range`) |
| `min_length`, `max_length` | `min_length`, `max_length` column checks (rule `length`) |
| `allowed_values` | `allowed_values` column check (rule `not_allowed`), split on `|` |
| `pattern` | `pattern` column check (rule `pattern_mismatch`) |
| `value_severity` | severity of the enabled value checks of that column: `out_of_range`, `not_allowed`, `pattern_mismatch`, `length` |
| `business_label` | Business metadata only (comment) |
| `fk_target_table`, `fk_target_column` | **Business metadata only (comment).** Floe does not check foreign keys |

### Severity precedence

`Guide.default_severity` → `Tables.default_severity` → `Tables.*_severity` →
`Columns.not_null_severity` / `value_severity` (only for checks that are enabled).
Allowed values: `warn`, `reject`, `abort`.

## Not in the workbook

Source and sink URIs, credentials, catalogs, partitioning, source data types. The engineer
sets these in `_domain.yml` or the entity files.

## The example content

The workbook ships with three tables (`customers`, `orders`, `order_lines`) in the `sales`
domain: renamed columns, a composite primary key (`order_lines`), single and composite
unique keys (`customers`), FK metadata, inherited and overridden severities, and value and
length checks. Replace the rows with your own.

## How the binary was produced

The repo has no XLSX writer dependency. The file was generated by a throwaway
`openpyxl` script (not committed) run with `uv run --with openpyxl`, then read back with
`fastexcel` to check sheet names and headers. It can be edited in Excel or LibreOffice.
