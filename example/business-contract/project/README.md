# Business contract example project

A runnable Floe project built from `../domain-template.xlsx` (the `sales` domain: `customers`, `orders`,
`order_lines`). It shows the split described in [the guide](../../../docs/guides/business-contract.md):

| File | Owner |
|---|---|
| `domains/sales/{customers,orders,order_lines}.yml` | Business: generated by `floe contract import`, never edited by hand |
| `domains/sales/_domain.yml` | Engineer: source and sink defaults, completed once (local CSV in, local Parquet out) |
| `config.yml` | Engineer: includes the domain |
| `in/sales/*_export.csv` | Sample data; each file is the entity's `source.resource` |

The inputs carry a few bad rows on purpose (a malformed email, a birth date before 1900, an unknown order status, a zero quantity),
so the run reports both accepted and rejected rows.

Run these from `example/business-contract/project` (needs the `xlsx` extra, `pip install 'floe-python[xlsx]'`):

```bash
# 1. The workbook is in sync with the YAML (exit 0; non-zero if they drifted)
floe contract import ../domain-template.xlsx --output-dir domains/sales --check

# 2. Validate and run
floe validate -c config.yml
floe run -c config.yml        # accepted Parquet in out/accepted, rejected rows in out/rejected, reports in report/

# 3. Generate the manifest the orchestrator connectors read
floe manifest generate -c config.yml -o manifest.json --deterministic
```

To regenerate the entity files from scratch, import into an empty directory
(`floe contract import ../domain-template.xlsx --output-dir /tmp/sales`) and copy the entity files over; `_domain.yml` is
yours and the importer never rewrites it.

## Where it is tested

- `tests/unit/contract/test_example_project.py`: re-import is a no-op, the manifest validates and carries keys and severities.
- `conformance/business_contract/`: a copy of this project recorded as a golden case (`uv run python conformance/check.py --case business_contract`). Change the example, then copy it there and re-record.
- `orchestrators/*/tests/fixtures/business_contract_manifest.json`: the generated manifest, loaded by the dagster-floe and airflow-floe tests.
