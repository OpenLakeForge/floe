# S3 Storage (MVP)

This document describes current S3 support in Floe.

## Requirements

Floe uses the standard AWS credential/provider chain. Configure access using
the usual environment variables, for example:

- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `AWS_SESSION_TOKEN` (if using temporary credentials)
- `AWS_REGION` or `AWS_DEFAULT_REGION`

## Config example

```yaml
storages:
  default: local
  definitions:
    - name: local
      type: local
    - name: s3_raw
      type: s3
      bucket: my-bucket
      region: eu-west-1
      prefix: raw/data

entities:
  - name: customers
    source:
      format: json
      options:
        json_mode: array
      path: inbound/customers
      storage: s3_raw
    sink:
      accepted:
        format: parquet
        path: outbound/customers
        storage: s3_raw
      rejected:
        format: csv
        path: outbound/customers_rejected
        storage: s3_raw
    policy:
      severity: reject
    schema:
      columns:
        - name: customer_id
          type: string
```

Resolved S3 URIs are formed as:

```
s3://<bucket>/<prefix>/<path>
```

## Supported behavior

- Inputs: CSV, TSV, JSON (array/ndjson), ORC, Parquet, XLSX, Avro, and XML via prefix listing + suffix filtering.
- Outputs:
  - Accepted parquet: each part is built in memory, then uploaded.
  - Accepted Iceberg: PyIceberg (and DuckDB for merges) write the table files directly.
  - Rejected CSV: built in memory, then uploaded.
  - Reports: JSON uploaded.

## Limitations

- Source path is treated as a prefix. A glob in the path (`*`, `?`) is matched against the
  listed keys and needs a non-empty literal prefix before the first wildcard.
- Only suffix filtering by format is applied (e.g., `.csv`, `.tsv`, `.json`, `.jsonl`, `.orc`, `.xlsx`, `.avro`, `.xml`).
- Recursive listing behavior is not configurable yet (S3 prefix lists are
  effectively recursive).
- Parquet/ORC input uses temp download + local read.
